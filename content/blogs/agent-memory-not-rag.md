# Agent Memory 为什么不只是 RAG

RAG 更像一次查询：给定当前问题，从外部语料中召回若干片段，再把片段交给模型。Agent Memory 则更像一个持续运行的状态系统：它必须知道什么被观察过、什么仍然成立、什么已经被修正，以及某条记忆曾经如何影响决策。

## 关键差别

- **时间**：事实在世界中何时成立，Agent 何时看到，系统何时接受。
- **版本**：新证据可能补充、覆盖或推翻旧记录。
- **依赖**：一条结论通常依赖若干证据与推导过程。
- **效用**：被频繁召回并不等于有价值；一次召回是否改善任务结果才更重要。
- **事务**：多条相关记忆的更新应保持一致，而不是各自独立覆盖。

## 一个直观例子

假设 Agent 在 4 月 15 日才得知 Alice 从 3 月 1 日开始担任项目负责人。此时至少有两个不同的问题：

1. 3 月 20 日，现实中的负责人是谁？
2. 3 月 20 日，当时的 Agent 认为负责人是谁？

普通向量检索很容易把这两个问题压成同一个最新摘要。一个更严格的 Memory 系统则需要保留 `valid_time`、`observed_time` 与 `committed_time`，从而恢复不同语义下的历史快照。

> Memory 的目标不是保存更多文本，而是在正确时刻恢复足以支持行动的状态与证据。
