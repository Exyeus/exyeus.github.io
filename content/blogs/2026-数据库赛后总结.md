#### 关于 Git Commit Message

Conventional Commits 给出了非常好用的基本结构：`<type>(<scope>): <description>`
例如：`perf(wal): split write and durability flush`

扩展成数据库比赛版本：性能结果，可以视情况 `git notes add <hash_prefix> ... write ...`

```shell
perf(wal): separate WAL write from durability sync

Problem:
Buffer-pool eviction called full fdatasync although WAL only
needs to precede dirty-page write.

Hypothesis:
fdatasync frequency dominates WAL path latency.

Change:
- add flush_log_buffer_to_disk()
- write buffered WAL without fdatasync
- keep flush_log_to_disk() for durable commit

Correctness:
WAL-before-page invariant preserved.

Expected:
Reduce fdatasync calls during eviction.

Refs:
experiment EXP-014
```
#### 关于 Worktree 的理论与简要用法

为了并行实验复制：

`rdb-v4/` `rmdb-final/` `rmdb-best/` `rmdb-final-final/`

这种东西很快会变成灾难。正确抽象是：

> Repository 保存历史。  
> Branch 保存实验方向。  
> Worktree 提供不同物理工作目录。

如此，则只有一条主线，并且不用频繁 stash & checkout。
#### 关于比赛之中的共享文档

比起单开一个腾讯文档，更成熟的东西叫：Architecture Decision Record，ADR。

它解决的是：发现代码里有个奇怪设计，却没人记得当初为什么这么做。核心原则就是：大型设计文档很快过期，而小型、模块化、跟随项目演化的设计记录更可能保持有效。

```shell
ADR-017: Stripe transaction writer claims

Status:
Accepted

Context:
Single global claim table introduces synchronization contention.

Options:
1. global mutex
2. 64 stripes
3. 128 stripes
4. per-page ownership

Decision:
Use 128 striped claim tables.

Reason:
A/B benchmark improved throughput by 6.98% with modest complexity.

Consequences:
Hash selection becomes part of hot path.
Future NUMA-aware partitioning remains possible.
```

#### 关于权衡

##### MVCC Version Chain

- GC 太懒 → 链越来越长
- GC 太勤 → GC 本身成为热点

Cicada 就把 **rapid garbage collection** 作为主要设计之一：迅速回收旧版本以缩小 working set、改善 cache locality。ERMIA 又是另一个非常值得看的 MVCC system，它把 SI、serial safety、latch-free indirection、logging、epoch resource management 放在一整个 scalable physical layer 里考虑，而不是单看一个 version chain。
